# Governance

## Project direction

Mahiva Codebase Mapping is governed by the maintainers of this repository. The project prioritizes deterministic static analysis, clear package boundaries, and incremental delivery.

## Decision making

- Major changes should be discussed in pull requests or issues.
- Breaking changes should be documented clearly and tested carefully.
- Public-facing behavior should remain consistent and explainable.

## Maintainer expectations

Maintainers are expected to:

- review changes with a focus on correctness and project direction
- preserve package boundaries and architectural consistency
- keep the project buildable, testable, and well documented

## Change control

Significant features, releases, and architecture decisions should be captured in documentation, issue discussions, or release notes so that the project remains understandable and maintainable over time.
